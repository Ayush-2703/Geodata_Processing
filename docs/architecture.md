# Architecture Documentation

## Overview

The pipeline is designed as a **modular, sequential, six-stage system** where each module is independently testable and produces a typed output passed to the next stage.

## Module Dependency Graph

```
run_pipeline.py
     │
     ├─► 01_data_ingestion.py     → IngestResult
     │         │
     ├─► 02_preprocessing.py      → PreprocResult   (uses IngestResult)
     │         │
     ├─► 03_bias_harmonization.py → HarmonResult    (uses Ingest + Preproc)
     │         │
     ├─► 04_ai_models.py          → ModelResult     (uses Ingest + Preproc + Harmon)
     │         │
     ├─► 05_change_detection.py   → ChangeResult    (uses Preproc + Model)
     │         │
     └─► 06_visualization.py      (uses all above results)
```

## Data Flow

### Input Formats
| Format | Description | Used By |
|--------|-------------|---------|
| GeoTIFF (.tif) | Single-band raster (uint16 DN values) | Modules 1–5 |
| CSV | Tabular reflectance + labels | Modules 1, 3, 4 |

### Output Formats
| Format | Description | Module |
|--------|-------------|--------|
| GeoTIFF (.tif, float32) | Preprocessed stack, QA, predictions | 2, 4, 5 |
| .pkl | Serialised sklearn model | 4 |
| .png | Publication figures (150–180 DPI) | 6 |
| .txt | Plain-text pipeline report | runner |
| .log | Timestamped execution log | runner |

## Design Decisions

### Why `module_runner.py`?
Python cannot directly `import` a module whose filename starts with a digit (e.g. `01_data_ingestion.py`). The `module_runner.py` utility uses `importlib.util.spec_from_file_location` to load modules by file path, bypassing the naming constraint while keeping the numbered filenames (which clearly communicate pipeline order).

### Why Random Forest + MLP?
- **Random Forest**: robust to outliers, provides feature importance, fast training
- **MLP**: captures non-linear interactions between spectral bands, serves as a comparison baseline
- Both are scikit-learn native → no GPU dependency, reproducible with `random_state`

### Why synthetic T1 for change detection?
With a single acquisition date, a simulated "before" image is generated by applying a 10-year historical land-use shift to the spectral indices. This demonstrates the algorithm on real spatial data. Real two-date workflows are supported via `--before-tif`.

### Spectral Index Choice
All five indices (NDVI, NDWI, MNDWI, NDBI, NBR) were chosen to cover distinct surface types: vegetation, open water, modified water, built-up, and soil/burn. This ensures the change detection module can differentiate between all major landscape change types.
